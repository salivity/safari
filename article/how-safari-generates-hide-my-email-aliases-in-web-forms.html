How Safari Generates Hide My Email Aliases in Web Forms

This article explains the technical and user-facing processes behind Safari’s Hide My Email integration. It covers how the browser detects email input fields on websites, connects with Apple's iCloud+ servers to dynamically generate random email aliases, and seamlessly autofills these credentials while syncing them to the user's Apple account for future use.

1. HTML Field Detection

The process begins when a webpage loads in Safari. Safari's rendering engine, WebKit, scans the page's Document Object Model (DOM) to identify forms. It looks for specific HTML attributes that indicate an email address is required, such as type="email", name="email", or autocomplete="email". Even if a website uses non-standard code, Safari uses local heuristics to analyze the text labels surrounding an input box to determine if it is asking for an email address.

2. Triggering the AutoFill Interface

When you click or tap inside the identified email field, Safari intercepts the interaction and activates its native AutoFill menu. Before displaying the menu, Safari checks the device's system state to verify two things: that the user is signed into an Apple ID, and that the account has an active iCloud+ subscription. Once verified, Safari displays the "Hide My Email" option directly in the dropdown menu or above the on-screen keyboard.

3. Server-Side Alias Generation

When you select the "Hide My Email" option, Safari does not generate the email address locally on your device. Instead, it sends an encrypted API request to Apple’s iCloud+ identity servers.

The iCloud server immediately generates a unique, random email address ending in @icloud.com. To make the alias somewhat readable and memorable while remaining random, Apple's algorithm combines two unrelated dictionary words (sometimes modified or pluralized) with a random two-character alphanumeric string, separated by periods or underscores (for example, nebula.catwalk_09@icloud.com). The server checks its database in real time to ensure this exact combination has never been used before.

4. Domain Binding and Preview

Once the server generates the alias, it sends the string back to Safari, which displays it in a preview pop-up overlay over the web form. Simultaneously, Safari reads the URL of the current webpage and extracts the primary domain name. It automatically populates a label for the alias using this domain name, ensuring you have a record of which website is receiving the random address. At this stage, the alias is only reserved temporarily; if you cancel the prompt or refresh the page, the address is discarded.

5. Activation, Keychain Syncing, and Form Injection

When you click "Continue" or "Use" in the Safari prompt, three final actions occur simultaneously:

  • Routing Activation: Safari tells the iCloud+ server to finalize the alias. Apple's mail servers establish a forwarding rule linking the new @icloud.com alias to your personal email inbox.
  • iCloud Keychain Storage: The alias, associated website domain, and creation date are saved to your iCloud Keychain. If you later create a password on the same form, Safari automatically binds the new password to the generated alias for seamless future logins.
  • DOM Injection: Safari's AutoFill engine programmatically inserts the generated email string directly into the HTML input field on the webpage and triggers the necessary web events (such as input and change events) so the website's JavaScript recognizes that the form has been filled out properly.
