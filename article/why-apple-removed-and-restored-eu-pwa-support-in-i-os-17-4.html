Why Apple Removed and Restored EU PWA Support in iOS 17.4

During the iOS 17.4 beta cycle in early 2024, Apple temporarily disabled standalone Progressive Web App (PWA) functionality in the European Union, downgrading Home Screen web apps into simple browser shortcuts. Apple initially made this move as a response to the EU's Digital Markets Act (DMA), claiming that supporting PWAs on newly mandated third-party browser engines posed severe security risks and required an unfeasible amount of engineering work. However, after facing massive backlash from web developers, consumer advocacy groups, and the threat of a formal investigation by European regulators, Apple reversed its decision. The company restored full PWA functionality for the public release of iOS 17.4 by deciding that all Home Screen web apps would simply continue to run directly on its native WebKit engine.

The Catalyst: The Digital Markets Act (DMA)

For years, Apple required all web browsers on iOS—including Chrome, Firefox, and Edge—to use its proprietary WebKit rendering engine. Under the European Union's Digital Markets Act, which went into effect in March 2024, Apple was designated as a "gatekeeper" and forced to open up its ecosystem.

One of the core requirements of the DMA was that Apple had to allow third-party browsers to use their own rendering engines (such as Google’s Blink or Mozilla’s Gecko) on iOS in the EU.

Why Apple Initially Removed PWA Functionality

Progressive Web Apps are websites that can be saved to a smartphone's Home Screen and function like native apps. They operate in a standalone window without a browser URL bar, can send push notifications, store data locally, and display badges on their icons.

On iOS, PWAs were built to rely entirely on Safari's WebKit engine to enforce strict iOS security and privacy sandboxing. When the DMA forced Apple to support alternative browser engines, a complication arose: how would iOS handle PWAs installed from non-WebKit browsers?

In February 2024, during the iOS 17.4 beta testing phase, Apple simply turned off standalone PWA functionality in the EU. Instead of opening as independent apps, Home Screen web apps merely opened as tabs inside the default web browser. Apple justified this removal with the following points:

  • Engineering Complexity: Apple stated that allowing third-party browser engines to power Home Screen PWAs would require building an entirely new integration architecture from scratch, which was not practical given the other massive changes required by the DMA.
  • Security and Privacy Risks: Without that new architecture, Apple claimed that malicious web apps using alternative engines could bypass iOS security protocols, read data from other apps, and access a user's camera, microphone, or location without proper system-level permission.
  • Low User Adoption: Apple argued that very few users actually utilized Home Screen web apps, making the massive engineering effort unjustifiable.

The Backlash and Regulatory Scrutiny

Apple's decision triggered immediate outrage from the developer community, led by groups like the Open Web Advocacy. Developers pointed out that stripping PWA functionality removed key features like push notifications and persistent local storage, breaking critical workflows for businesses and users who relied on web apps.

More importantly, critics argued that Apple's move was blatantly anti-competitive. Because PWAs can be installed directly from the web, they represent the only viable way for developers to distribute software to iOS users without going through the App Store and paying Apple's commissions. By crippling PWAs right as the DMA was supposed to increase competition, Apple appeared to be violating the spirit of the law.

Soon after, the European Commission stepped in. EU regulators began sending formal requests for information to Apple and app developers to assess the impact of the PWA removal, signaling that a full antitrust investigation into the matter was imminent.

The Reversal and Compromise

Faced with mounting public pressure and the threat of heavy fines from the European Commission, Apple backed down in early March 2024, just days before the DMA compliance deadline.

Apple announced that it would restore the existing Home Screen web app capability in the EU with the final release of iOS 17.4. To bypass the security and engineering hurdles it had previously cited, Apple implemented a straightforward compromise: all Home Screen PWAs in the EU must still be built directly on WebKit.

Even if an EU user creates a Home Screen web app using an alternative browser running a non-WebKit engine, the resulting PWA is forced to run on Apple’s WebKit engine and adhere to its security architecture. While this meant alternative browser engines still could not power their own PWAs, it successfully preserved the existing functionality of web apps for developers and users across the European Union.
