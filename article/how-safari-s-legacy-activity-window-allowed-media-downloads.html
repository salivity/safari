How Safari's Legacy Activity Window Allowed Media Downloads

Early versions of Apple's Safari web browser featured a built-in utility called the Activity Window, which provided users with a real-time list of every individual file a webpage loaded. This article explains how the Activity Window functioned, the specific steps users took to identify and download embedded audio and video files directly from this list, and why Apple eventually retired the feature in later versions of the browser.

What Was the Activity Window?

Available in Safari up until version 5, the Activity Window was a diagnostic tool accessible to all users without needing to enable advanced developer modes. By navigating to the "Window" menu and selecting "Activity" (or pressing the keyboard shortcut Command + Option + A), a floating palette would appear on the screen.

This window displayed a collapsible hierarchy of every webpage currently open in the browser. Expanding a webpage's tree revealed a complete list of every single asset the browser had requested from the web server to build that page. This included HTML documents, CSS stylesheets, JavaScript files, images, and embedded media.

Identifying Media Files by Size

Next to the URL of each loaded resource, the Activity Window displayed the exact file size or the current loading status. This made finding hidden media files effortless.

While text files, scripts, and standard images typically measured in kilobytes (KB), audio and video files measured in megabytes (MB). If a user was watching a video on a site like YouTube or listening to an embedded song on a blog, they only needed to scroll through the Activity Window and look for the single line item that was several megabytes in size and actively ticking upward as it buffered.

How the Download Trick Worked

In the early days of web video, most media was delivered via progressive download using plugins like Adobe Flash or Apple QuickTime. Even when a website hid the media behind a custom Flash player to prevent saving, the player still had to request the raw .flv, .mp4, or .mp3 file from a server. The Activity Window logged this background request, exposing the direct URL to the raw media file.

Once the user located the large media file in the Activity Window list, downloading it required a simple keyboard and mouse combination:

  1. Highlight the specific resource line in the Activity Window.
  2. Hold down the Option (Alt) key on the keyboard.
  3. Double-click the highlighted item.

Normally, double-clicking an item in the Activity Window simply opened that specific asset in a new Safari tab. However, holding the Option key is a universal macOS modifier for forcing a download. Option-double-clicking the URL instructed Safari's download manager to fetch the raw file directly from the server and save it to the user's Downloads folder. Alternatively, users could press Command + C to copy the direct URL, paste it into the main Downloads window, and trigger the save from there.

The Disappearance of the Activity Window

Apple removed the Activity Window in 2012 with the release of Safari 6. The company consolidated all diagnostic tools into the Web Inspector, which stays hidden unless the user manually activates the "Develop" menu in Safari's preferences.

While users can still view network requests in the modern Web Inspector's "Network" tab, the old downloading trick rarely works today. Modern websites no longer load single, monolithic video files. Instead, they use adaptive bitrate streaming protocols—such as HTTP Live Streaming (HLS)—which chop videos into hundreds of tiny, unplayable text and media segments. Because the browser now loads dozens of tiny .ts or .m4s fragments instead of one large .mp4 file, the straightforward download method facilitated by the legacy Activity Window is now a thing of the past.
