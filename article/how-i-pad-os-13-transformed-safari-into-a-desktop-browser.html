How iPadOS 13 Transformed Safari Into a Desktop Browser

The release of iPadOS 13 marked a significant milestone for the iPad, notably by upgrading the Safari web browser from a scaled-up mobile app into a true desktop-class browsing experience. This article explores the key features introduced in iPadOS 13—such as automatic desktop website rendering, a dedicated download manager, enhanced tab management, and comprehensive keyboard shortcuts—that bridged the gap between the iPad and traditional laptop computers for web-based workflows.

Default Desktop Website Rendering

Before iPadOS 13, Safari frequently loaded stripped-down mobile versions of websites because it identified itself to web servers as an iOS device. iPadOS 13 changed Safari’s User-Agent string to match Safari on macOS, forcing websites to deliver their full desktop versions by default.

To ensure these desktop sites worked on a tablet, Apple engineered Safari to automatically scale pages to fit the iPad’s screen dimensions. Furthermore, the browser translated legacy mouse-based interactions—such as hover menus and scroll bars—into touch gestures. This fundamental change made complex web applications like Google Docs, Squarespace, Jira, and WordPress fully functional on the iPad without requiring dedicated apps.

A Built-In Download Manager

A true desktop browser requires the ability to download and manage files directly from the web. iPadOS 13 introduced a dedicated Download Manager located in the top toolbar of the Safari interface.

Users gained the ability to click a download link, monitor the progress of the file, pause or resume the transfer, and view a history of recently downloaded items. By default, downloaded files were routed to a designated "Downloads" folder in the updated Files app, allowing users to save documents, zip archives, images, and audio files locally on the iPad, to an external USB drive, or directly to iCloud Drive.

The Website View Menu and Per-Site Settings

iPadOS 13 added an "AA" icon to the left side of the address bar, consolidating vital page controls into one accessible menu. From this Website View menu, users could:

  • Adjust the text size and zoom level of a webpage without breaking the overall layout.
  • Toggle Reader View for distraction-free reading.
  • Request the mobile version of a website if preferred.
  • Access specific website settings to manage permissions for the camera, microphone, and location.

Crucially, Safari was updated to remember these preferences on a per-site basis. If a user set a specific zoom level for a frequented website, Safari automatically applied that setting on future visits.

Enhanced Tab Management and Multitasking

Managing multiple webpages became significantly more efficient with the introduction of multi-window support in iPadOS 13. Users could open two separate Safari windows side-by-side using Split View, making it easy to cross-reference information or drag and drop content between pages.

Additional tab management features included:

  • Switch to Tab: Typing a URL in the Smart Search field that matched an already open tab prompted the user to switch directly to that existing tab rather than opening a duplicate.
  • Auto-Close Tabs: Users could configure Safari to automatically close forgotten tabs after a day, a week, or a month.
  • Bookmarking Tabs: Open tabs could be grouped and saved together as a single bookmark folder for future sessions.

Expanded Keyboard Shortcuts and Upload Controls

For users pairing their iPad with a Smart Keyboard or Bluetooth keyboard, iPadOS 13 added more than 30 new keyboard shortcuts to Safari. These shortcuts mirrored the macOS browsing experience, enabling users to navigate between tabs, reload pages, search within a webpage, and open the downloads list without touching the screen.

Additionally, uploading files to the web was streamlined. When uploading an image, Safari offered built-in controls to resize the photo (selecting between small, medium, large, or actual size) before sending it, saving bandwidth and time when working with web-based content management systems.
